## What is installed here

- **Local model servers.** These are bound to this machine only and are not reachable from the network.
  - Ollama at `http://127.0.0.1:11434`. It has an OpenAI-compatible API at `/v1` and an Anthropic-compatible API at `/v1/messages`. Models whose names start with `lab-` have the lab's system prompt built in.
  - LM Studio at `http://127.0.0.1:1234/v1`, when its server is started.
- **Cornell AI Gateway.** It speaks the OpenAI-compatible API and is available at `$CORNELL_AI_BASE_URL` when the user has run `lab-login`.
- **Package managers.** Always use these; never use system Python, `sudo pip` or a global `npm install` into system paths.
  - Python: `uv` (`uv init`, `uv add <pkg>`, `uv run script.py`, `uv tool install <cli>`).
  - Node: `nvm` (`nvm use --lts`).
- **Lab helpers** (in `$LAB_KIT/bin`). Run `lab help` to list them. The main ones:
  - `lab-status` checks health.
  - `lab-scan <file>` scans text for identifiers. **Run it before analyzing any participant data.**
  - `lab-models list` lists models.
  - `labllm` is a Python library and CLI for calling any backend. It sends exactly the system and user prompts the user writes, with no hidden system prompt, and runs the identifier scan first.
  - `lab new <project>` / `lab init` set up a project as its own git repo with uv and a safety hook.
- **Shared locations:**
  - Models: `$LAB_MODELS`
  - Projects: `$LAB_PROJECTS/<netid>/<project>` (default `/Users/Shared/research`). Each one is a separate git repo, outside the lab-llm tree. Never create project files inside `$LAB_ROOT`.
  - Kit and skills: `$LAB_KIT`

## How to behave here

- Prefer local models for anything that touches research data.
- For new analysis work, use `lab new` (or `lab init` in an existing folder) and call models through `labllm`. See the `local-llm-api` skill.
- Keep the user's prompts theirs. Put system and user prompts in `prompts/` as files, and don't add lab boilerplate to them unless asked.
- Help users commit early and often (see the `research-version-control` skill). Never commit `data/`, `outputs/` or keys. If the pre-commit hook blocks a commit, explain why; don't bypass it.
- Before reading a data file, run `lab-scan` on it. If it reports findings, stop and follow constitution §6.1.
- Don't store secrets (API keys, tokens) in files. Keys come from the environment only.
- Lab skills are listed in your skills directory. Use them when they match the task.
